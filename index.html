Probability & Statistics

BCA 3001T · Theory Only · 3 Credits

3 Credits Theory Only Formula Heavy
Exam mein zaroor aata hai
Aksar aata hai
Kabhi kabhi aata hai
1
Probability — Basics & Theorems
Must Do ▶
  • Sample Space & Events: Sample space (S), Event (subset of S), Types — Simple, Compound, Mutually Exclusive, Exhaustive, Equally Likely, Independent events — definitions + examples
  • Classical Definition: P(A) = favourable outcomes / total outcomes. Limitations of classical definition.
  • Addition Theorem: P(A∪B) = P(A) + P(B) - P(A∩B). For mutually exclusive: P(A∪B) = P(A) + P(B). Proof + example both required.
  • Multiplication Theorem: P(A∩B) = P(A) × P(B|A). For independent events: P(A∩B) = P(A) × P(B).
  • Conditional Probability: P(A|B) = P(A∩B) / P(B). Full formula + numerical example.
  • Bayes' Theorem: Formula, proof, complete numerical problem — this is a 10-mark question every year.
  • Statistical (Empirical) Definition: P(A) = lim(n→∞) f/n. Comparison with classical.
  • Axiomatic Definition: Kolmogorov's axioms — 3 axioms only, brief.
2
Random Variables & Probability Distributions
Must Do ▶
  • Random Variable: Definition — discrete (countable values) vs continuous (range of values). Examples of each.
  • PMF & PDF: Probability Mass Function for discrete, Probability Density Function for continuous — properties, examples.
  • CDF: Cumulative Distribution Function F(x) = P(X ≤ x). Properties: non-decreasing, 0 to 1.
  • Mathematical Expectation: E(X) = Σ x·P(x). Properties: E(aX+b) = aE(X)+b, E(X+Y) = E(X)+E(Y).
  • Variance: Var(X) = E(X²) – [E(X)]². Standard Deviation = √Var(X). Numerical problems on E(X) and Var(X).
  • Moments: Raw moments μ'r = E(Xr), Central moments μr — first 4 moments.
3
Binomial, Poisson & Normal Distributions
Must Do ▶
  • Binomial Distribution: P(X=r) = ⁿCᵣ pʳ qⁿ⁻ʳ. Mean = np, Variance = npq. Conditions for binomial. Derivation + 2 numericals.
  • Poisson Distribution: P(X=r) = e⁻λ λʳ/r!. Mean = Variance = λ. "Poisson as limiting case of Binomial" — this proof is a CCSU favourite.
  • Normal Distribution: Bell curve properties — symmetric, mean=median=mode, area under curve. Standard Normal Z = (X-μ)/σ. Z-table usage for finding probabilities.
  • Normal as limit of Binomial: When n→∞, Binomial → Normal. Brief derivation.
  • Fitting Binomial/Poisson: Given data, fit a theoretical distribution — numerical.
4
Central Tendency & Dispersion
Important ▶
  • Mean: Arithmetic Mean (AM) for raw/grouped data. Weighted Mean. Geometric Mean (GM) = (x₁·x₂…xₙ)^(1/n). Harmonic Mean (HM). Relationship: AM ≥ GM ≥ HM.
  • Median: For raw data (middle value) and grouped data (M = L + [(n/2 - cf)/f] × h). Quartiles Q1, Q3.
  • Mode: For raw data (most frequent) and grouped data (Z = L + [f₁-f₀/2f₁-f₀-f₂] × h).
  • Standard Deviation & Variance: σ² = Σ(xᵢ-x̄)²/n for population; s² = Σ(xᵢ-x̄)²/(n-1) for sample. Numerical calculation must be practiced.
  • Range, Mean Deviation: Range = Max - Min. MD from mean and from median. Coefficient of MD.
  • Coefficient of Variation: CV = (σ/x̄) × 100. Used to compare variability of two datasets.
  • Skewness & Kurtosis: Positive/Negative skew, Karl Pearson's coefficient of skewness. Kurtosis types (mesokurtic, leptokurtic, platykurtic) — definitions only.
5
Correlation & Regression
Must Do ▶
  • Correlation: Definition, types (positive/negative/zero, perfect/partial). Scatter diagram interpretation.
  • Karl Pearson's r: r = Σ[(x-x̄)(y-ȳ)] / √[Σ(x-x̄)² × Σ(y-ȳ)²]. Properties: -1 ≤ r ≤ +1. Full numerical calculation guaranteed in exam.
  • Spearman's Rank Correlation: rₛ = 1 - [6ΣD²/n(n²-1)]. For tied ranks formula. Numerical problem must be practiced.
  • Regression Lines: Y on X: (y-ȳ) = byx(x-x̄). X on Y: (x-x̄) = bxy(y-ȳ). Two regression lines, regression coefficients byx and bxy.
  • Relationship: r² = byx × bxy. This property appears in every CCSU paper.
  • Standard Error of Estimate: Measuring accuracy of regression prediction.
6
Sampling & Hypothesis Testing
Important ▶
  • Sampling: Population vs Sample. Types — Random, Stratified, Systematic, Cluster. Sampling vs Census.
  • Hypothesis Testing: Null Hypothesis H₀, Alternative Hypothesis H₁. Type I Error (α) and Type II Error (β).
  • t-test: One sample t-test for mean. t = (x̄ - μ) / (s/√n). Degrees of freedom.
  • Chi-Square Test: χ² = Σ[(O-E)²/E]. Test of independence, goodness of fit. Contingency table.
  • Z-test: For large samples (n > 30). Z = (x̄ - μ) / (σ/√n).
  • F-test / ANOVA: Brief intro — comparing variances.

Database Management Systems

BCA 3002T + BCA 3002P · Theory + Practical · 5 Credits

5 Credits — HIGHEST! Theory + Lab SQL Must
Exam mein zaroor aata hai
Aksar aata hai
Kabhi kabhi aata hai
1
Introduction to DBMS
Important ▶
  • Data vs Information: Data = raw facts. Information = processed meaningful data. Examples needed.
  • Database & DBMS: Database = organized collection of related data. DBMS = software that manages database. Characteristics of DBMS.
  • File System vs DBMS: CCSU favourite comparison — Redundancy, Inconsistency, Atomicity, Concurrency issues in File System. Table format answer.
  • DBMS Architecture: 1-tier (direct), 2-tier (client-server), 3-tier (client-app server-DB server). Diagram for each. ANSI/SPARC 3-level architecture (External, Conceptual, Internal) — very important.
  • Data Abstraction: Physical level, Logical level, View level. Data Independence — Physical and Logical.
  • Schema and Instance: Schema = structure of database (doesn't change). Instance = data at a point in time (changes).
  • Database Users: DBA (rights and duties), Application Programmer, Naive User, Sophisticated User.
  • Data Models: Hierarchical, Network, Relational, Object-Oriented — brief comparison. CCSU mostly focuses on Relational.
2
ER Model & Relational Model
Must Do ▶
  • Entity & Entity Types: Strong Entity vs Weak Entity. Entity Set.
  • Attributes: Simple, Composite, Single-valued, Multivalued, Derived, Key attribute — definitions + ER symbols for each.
  • Relationships: Relationship type, Relationship set. Degree (unary, binary, ternary). Cardinality Ratios: 1:1, 1:N, M:N with examples.
  • Participation Constraints: Total participation (double line) vs Partial participation (single line) in ER diagram.
  • ER Diagram: Drawing complete ER diagram for a given problem (Library, Bank, Hospital, University) — 100% exam question. Know all symbols: rectangle=entity, ellipse=attribute, diamond=relation, line=link.
  • Converting ER to Relational Schema: Rules for 1:1, 1:N, M:N relationships. Mapping weak entities. This is a 10-mark question.
  • Relational Model: Relation (table), Tuple (row), Attribute (column), Domain, Degree (number of attributes), Cardinality (number of tuples).
  • Keys: Super Key, Candidate Key, Primary Key, Alternate Key, Foreign Key — definitions + examples. Key differences in table format.
  • Integrity Constraints: Entity Integrity (PK ≠ NULL), Referential Integrity (FK must match PK or be NULL), Domain Constraint.
3
Relational Algebra
Important ▶
  • SELECT (σ): σ condition(R). Filters rows. Example: σ age>25(Employee).
  • PROJECT (π): π col1,col2(R). Filters columns. Example: π name,salary(Employee).
  • RENAME (ρ): ρ new_name(R). Renames relation.
  • Set Operations: UNION (∪), INTERSECTION (∩), SET DIFFERENCE (−) — compatibility conditions (same degree, compatible domains).
  • CARTESIAN PRODUCT (×): R × S. All combinations. Degree = degree(R) + degree(S), Cardinality = |R| × |S|.
  • JOIN Types: Natural Join (⋈), Theta Join, Equi Join, Left/Right/Full Outer Join. Difference between them. JOIN vs CARTESIAN PRODUCT.
  • Division (÷): R ÷ S. Used for "for all" type queries.
  • Extended RA: Aggregate functions in RA — Generalized Projection, Aggregate functions.
4
SQL — Full Coverage
Must Do ▶
  • DDL: CREATE TABLE (with constraints), ALTER TABLE (ADD/MODIFY/DROP column), DROP TABLE, TRUNCATE TABLE. Difference between DROP and TRUNCATE.
  • DML: INSERT INTO, UPDATE SET WHERE, DELETE FROM WHERE, SELECT (all forms).
  • SELECT Clauses: WHERE, ORDER BY (ASC/DESC), GROUP BY, HAVING, DISTINCT, LIMIT. Know when to use GROUP BY vs WHERE.
  • Aggregate Functions: COUNT(*), SUM(col), AVG(col), MAX(col), MIN(col). Use with GROUP BY. HAVING vs WHERE — key difference.
  • SQL JOINs: INNER JOIN, LEFT OUTER JOIN, RIGHT OUTER JOIN, FULL OUTER JOIN, SELF JOIN, CROSS JOIN — syntax + example query for each.
  • Subqueries: Single-row subquery, Multi-row subquery (IN, ANY, ALL). Correlated vs Non-correlated subqueries. EXISTS operator.
  • Views: CREATE VIEW, DROP VIEW. Advantages of views. Updatable vs non-updatable views.
  • Indexes: CREATE INDEX, types (clustered, non-clustered), advantages and trade-offs.
  • Constraints in SQL: NOT NULL, UNIQUE, PRIMARY KEY, FOREIGN KEY, CHECK, DEFAULT — inline and table-level syntax.
  • DCL & TCL: GRANT, REVOKE (DCL). COMMIT, ROLLBACK, SAVEPOINT (TCL).
5
Normalization
Must Do ▶
  • Anomalies: Insertion Anomaly, Deletion Anomaly, Update Anomaly — with examples. Why normalization is needed.
  • Functional Dependency: X → Y means X determines Y. Types: Full FD, Partial FD, Transitive FD. Armstrong's Axioms: Reflexivity, Augmentation, Transitivity.
  • 1NF: No repeating groups, all attributes atomic. Example of non-1NF table and its conversion.
  • 2NF: 1NF + No Partial Dependency (every non-key attribute fully depends on entire PK). Applies only when PK is composite. Example conversion.
  • 3NF: 2NF + No Transitive Dependency (non-key attribute should not depend on another non-key attribute). Full example with decomposition.
  • BCNF: For every FD X → Y, X must be a superkey. Stricter than 3NF. Example where 3NF holds but BCNF fails.
  • 4NF & 5NF: Brief definition only — Multi-valued dependency (4NF), Join dependency (5NF).
6
Transactions, Concurrency & Recovery
Must Do ▶
  • Transaction: Unit of work — sequence of operations. ACID Properties: Atomicity (all or nothing), Consistency (valid state to valid state), Isolation (concurrent transactions don't interfere), Durability (committed changes persist).
  • Transaction States: Active → Partially Committed → Committed / Failed → Aborted. State diagram required.
  • Concurrency Problems: Lost Update (W-W conflict), Dirty Read (W-R conflict), Unrepeatable Read, Phantom Read — example for each.
  • Schedules: Serial vs Non-serial. Serializable schedule. Conflict Serializability — Precedence Graph method.
  • Lock-based Protocols: Shared Lock (S), Exclusive Lock (X). Lock compatibility matrix. Two-Phase Locking (2PL) — Growing phase, Shrinking phase. Strict 2PL.
  • Deadlock: Definition, conditions (Mutual Exclusion, Hold & Wait, No Preemption, Circular Wait). Detection (Wait-for graph), Prevention (Wait-Die, Wound-Wait), Avoidance (Banker's Algorithm).
  • Recovery: Log-based recovery (UNDO/REDO). Checkpoint. Shadow Paging concept.
  • Timestamp Ordering: Thomas Write Rule, basic timestamp protocol.
7
File Organization & Indexing
Important ▶
  • File Organization Types: Sequential, Heap (Unordered), Hash, Indexed — advantages and disadvantages of each.
  • Indexing: Dense vs Sparse Index. Primary Index, Secondary Index, Clustering Index. Why indexing speeds up queries.
  • B-Tree: Properties — balanced, all leaves at same level, minimum/maximum keys per node. Insertion and search operations.
  • B+ Tree: Difference from B-Tree — data only in leaf nodes, leaf nodes linked. Why B+ Tree preferred for databases.
  • Hashing: Static hashing, Dynamic hashing (Extendible hashing). Hash collision handling — Linear probing, Chaining.

Software Engineering

BCA 3003T · Theory Only · 3 Credits

3 Credits Theory Only Diagram Scoring
Exam mein zaroor aata hai

Kabhi kabhi aata hai
1
Introduction & Software Process
Important ▶
  • Software: Definition (IEEE) — programs + documentation + data. Types: System software, Application software, Scientific, Embedded, Web, AI software.
  • Software Crisis: What it is, causes (increasing complexity, lack of management, poor design), consequences (cost overrun, schedule slippage, poor quality). Very common CCSU question.
  • Software Engineering: IEEE definition. Goals — reliability, efficiency, maintainability. Difference from programming.
  • SDLC Phases: Planning → Requirements → Design → Coding → Testing → Maintenance. Brief explanation of each phase.
  • Software Characteristics: Software is developed not manufactured. Software does not wear out. Software is custom built. Complexity vs hardware.
  • Software Process Models overview: Prescriptive vs Agile. Why different models exist for different project types.
2
SDLC Models — All Models with Diagrams
Must Do ▶
  • Waterfall Model: Linear sequential model. 6 phases with feedback arrows. Advantages (simple, well-documented), Disadvantages (no flexibility, testing at end). When to use. Diagram required.
  • Prototype Model: Build quick prototype, get feedback, refine. Types: Throwaway/Rapid Prototyping, Evolutionary Prototyping. Advantages (user involvement), Disadvantages (may become permanent). Diagram.
  • Spiral Model: Boehm's model. 4 quadrants: Planning, Risk Analysis, Engineering, Evaluation. Risk-driven, iterative. Advantages (risk management), Disadvantages (expensive, complex). Diagram.
  • Incremental Model: Core product first, then add features incrementally. Comparison with Iterative model.
  • RAD Model: Rapid Application Development. 4 phases: Business Modelling, Data Modelling, Process Modelling, Application Generation. Best for < 3 months projects. Diagram.
  • Agile Model: 12 Agile principles (know at least 4). Scrum framework: Product Backlog, Sprint (2-4 weeks), Sprint Backlog, Daily Scrum, Sprint Review, Sprint Retrospective. Diagram of Scrum.
  • V-Model: Verification and Validation at each stage. Each development phase maps to testing phase. When to use.
3
Requirements Engineering & System Modelling
Must Do ▶
  • Requirements Engineering Process: Elicitation → Analysis → Specification → Validation. Brief definition of each.
  • Functional vs Non-functional Requirements: Functional = what system does (features, functions). Non-functional = how well it does it (performance, security, reliability). Examples of each — CCSU exam staple.
  • SRS Document: Software Requirements Specification. IEEE format. Characteristics: Complete, Consistent, Unambiguous, Verifiable, Traceable. Contents of SRS.
  • DFD (Data Flow Diagram): 4 symbols — External Entity (rectangle), Process (circle/rounded), Data Store (open rectangle), Data Flow (arrow). Level 0 (Context), Level 1, Level 2. Practice drawing for Library/ATM system — 10-mark question.
  • Feasibility Study: Technical feasibility, Economic feasibility (cost-benefit), Operational feasibility, Schedule feasibility.
  • Data Dictionary: Definition, contents — name, alias, description, data type, length, range, validation rules.
  • Decision Tree & Decision Table: For complex business logic representation.
4
Software Design — Coupling, Cohesion & UML
Must Do ▶
  • Design Concepts: Abstraction (procedural, data, control), Modularity (why break into modules), Information Hiding, Stepwise Refinement, Structural Partitioning.
  • Coupling (worst to best): Content Coupling → Common Coupling → Control Coupling → Stamp Coupling → Data Coupling. Definitions + examples. Low coupling = good design. Table format answer.
  • Cohesion (worst to best): Coincidental → Logical → Temporal → Procedural → Communicational → Sequential → Functional. Definitions + examples. High cohesion = good design. Table format.
  • UML Use Case Diagram: Actors, Use Cases, System Boundary. <> and <> relationships. Draw for Library System / ATM. Practice 2 complete examples.
  • UML Class Diagram: Class (name, attributes, methods). Relationships: Association, Aggregation, Composition, Inheritance (Generalization). Multiplicity notation.
  • UML Sequence Diagram: Shows object interactions over time. Lifelines, Messages (synchronous/asynchronous), Activation bars.
  • UML Activity Diagram: Flowchart-like. Start, End, Activity, Decision, Fork, Join nodes. Used for workflow modelling.
  • UML State Diagram: States, Transitions, Events, Actions. For objects with complex lifecycle.
5
Software Testing
Must Do ▶
  • Verification vs Validation: Verification = "Are we building the product right?" (reviews, walkthroughs). Validation = "Are we building the right product?" (actual testing). V&V distinction is a frequent question.
  • Testing Levels: Unit Testing (individual module), Integration Testing (combine modules — Top-down, Bottom-up, Big Bang), System Testing (whole system), Acceptance Testing (user acceptance, alpha/beta).
  • Black Box Testing: Tests without internal code knowledge — based on input/output. Techniques: Equivalence Partitioning (divide input into classes), Boundary Value Analysis (test boundaries), Decision Table Testing.
  • White Box Testing: Tests with internal code knowledge. Coverage criteria: Statement Coverage (every statement executed), Branch Coverage (every branch tested), Path Coverage (every path tested). McCabe's Cyclomatic Complexity = E - N + 2P.
  • Alpha vs Beta Testing: Alpha = done by in-house testers at developer's site. Beta = done by real users at their site. Order: Alpha first, then Beta.
  • Regression Testing: Re-test after changes to ensure nothing broke. Smoke Testing: basic tests to check if build is stable enough for detailed testing.
  • Performance Testing: Load testing, Stress testing, Spike testing. Brief definitions.
6
Software Metrics, Maintenance & Project Management
Important ▶
  • Software Metrics: LOC (Lines of Code) — advantages (simple) and disadvantages (language dependent). Function Points — counts functions not lines. Halstead Metrics — program vocabulary, length, volume.
  • COCOMO Model: Constructive Cost Model. Basic COCOMO: Effort = a × (KDSI)^b, Time = c × (Effort)^d. Three modes: Organic, Semi-detached, Embedded. Brief formulas + application.
  • Software Maintenance Types: Corrective (fix bugs), Adaptive (adapt to new environment), Perfective (improve performance/features), Preventive (prevent future problems). Know all 4 with examples.
  • Software Re-engineering: Forward engineering, Reverse engineering, Re-engineering concept.
  • Risk Management: Risk identification, Risk analysis (probability × impact), Risk planning, Risk monitoring.
  • CASE Tools: Upper CASE (requirements, design), Lower CASE (coding, testing). Examples: Rational Rose, Visio.

Python Programming

1
Basics — Variables, Data Types & Operators
Must Do ▶
  • Python Features: Interpreted, Dynamically typed, Object-oriented, High-level, Easy syntax. Why Python is popular.
  • Variables & Naming Rules: No declaration needed. Dynamic typing. Variable naming: starts with letter/_, no keywords. Multiple assignment: a, b = 1, 2.
  • Data Types: int (10, -5), float (3.14), complex (2+3j), bool (True/False), str ("hello"), list ([1,2,3]), tuple ((1,2,3)), dict ({"a":1}), set ({1,2,3}), NoneType (None).
  • Type Conversion: Implicit (int + float = float automatically). Explicit: int("5"), float("3.14"), str(10), list((1,2)), tuple([1,2]).
  • Operators: Arithmetic (+,-,*,/,//,%,**), Comparison (==,!=,<,>,<=,>=), Logical (and, or, not), Assignment (=,+=,-=,*=,/=), Identity (is, is not), Membership (in, not in), Bitwise (&,|,^,~,<<,>>).
  • Input/Output: input() returns string — always convert. print() with sep, end parameters. f-strings: f"Name: {name}". format(): "{}".format(x).
  • Comments: # single line, ''' multiline '''. Indentation rules — mandatory in Python.
2
Strings & Conditional Statements
Must Do ▶
  • String Basics: Immutable. Indexing (s[0]), Negative indexing (s[-1]). Slicing: s[start:end:step]. Concatenation (+), Repetition (*).
  • String Methods: len(), upper(), lower(), strip()/lstrip()/rstrip(), split(sep), join(iterable), replace(old,new), find(sub), count(sub), startswith(prefix), endswith(suffix), title(), capitalize(), isdigit(), isalpha(), isalnum().
  • if-elif-else: Syntax (colon + indentation). Nested if. Short form: value = x if condition else y (ternary).
  • String Formatting: % operator: "Hello %s" % name. .format(): "Hello {}".format(name). f-string: f"Hello {name}" — most modern way.
  • String Comparison: Lexicographic comparison. in operator for substring check. ord() and chr() functions.
3
Lists, Tuples, Dictionary & Set
Must Do ▶
  • List: Mutable, ordered, allows duplicates. Methods: append(x), extend(iterable), insert(i,x), remove(x), pop(i), sort(), reverse(), index(x), count(x), copy(), clear(). List slicing. Nested lists.
  • List Comprehension: [expression for item in iterable if condition]. E.g., squares = [x**2 for x in range(10)]. This is asked as theory + code question.
  • Tuple: Immutable, ordered, allows duplicates. When to use tuple vs list. Packing: t = 1,2,3. Unpacking: a,b,c = t. Single element tuple: (1,). Methods: count(), index().
  • Dictionary: Mutable, key-value pairs, keys unique. Methods: keys(), values(), items(), get(key,default), update(dict2), pop(key), del d[key], clear(). Dictionary comprehension. Nested dict.
  • Set: Unordered, no duplicates. Operations: union (|), intersection (&), difference (-), symmetric_difference (^). Methods: add(x), remove(x), discard(x), union(), intersection(), issubset(), issuperset(). Frozenset (immutable set).
  • Comparison Table: List vs Tuple vs Set vs Dictionary — mutability, ordering, duplicates, syntax. This table appears in exams.
4
Loops
Must Do ▶
  • for Loop: for x in iterable: Iterating over list, tuple, string, range(). range(start, stop, step). Nested for loops. for with else clause.
  • while Loop: while condition: Infinite loop with break. while with else clause. Counter-controlled and sentinel-controlled loops.
  • break: Exits the loop immediately. Useful inside nested loops. Example: search loop.
  • continue: Skips current iteration, continues to next. Example: skip even numbers.
  • pass: Do nothing placeholder. Used in empty function/class body or empty if block.
  • enumerate(): enumerate(iterable, start=0) — gives (index, value) pairs. Useful alternative to range(len(list)).
  • zip(): Combines two iterables element-wise. for a, b in zip(list1, list2).
5
Functions & Recursion
Must Do ▶
  • Function Definition: def function_name(params): ... return value. Function with no return returns None. Calling functions. Docstrings.
  • Parameters: Positional parameters. Default parameters: def greet(name="World"). Keyword arguments: greet(name="Alice"). *args (tuple of positional), **kwargs (dict of keyword).
  • Scope (LEGB): Local → Enclosing → Global → Built-in. global keyword to modify global inside function. nonlocal for nested functions.
  • Lambda Functions: lambda args: expression. Anonymous functions. E.g., square = lambda x: x**2. Use in sorted(), map(), filter().
  • Recursion: Function calling itself. Base case (stopping condition) + recursive case. Examples: Factorial (n! = n × (n-1)!), Fibonacci (F(n) = F(n-1)+F(n-2)), Sum of digits. Stack overflow if no base case.
  • map(), filter(), reduce(): map(func, iterable), filter(func, iterable), reduce(func, iterable) from functools. Use with lambda.
  • Generators: yield keyword. Generator functions return iterator. Memory efficient. next() function.
6
File Handling
Must Do ▶
  • Opening Files: open(filename, mode). Modes: 'r' (read), 'w' (write, creates/overwrites), 'a' (append), 'r+' (read+write), 'rb'/'wb' (binary). Always close file or use with statement.
  • Reading: file.read() — entire file as string. file.readline() — one line. file.readlines() — list of all lines. Iterating: for line in file: ...
  • Writing: file.write(string), file.writelines(list). Write does NOT add newline automatically — add \n manually.
  • with Statement: with open('file.txt', 'r') as f: ... Automatically closes file even if exception occurs. Best practice — CCSU exams expect this.
  • File Pointer: file.tell() — current position. file.seek(offset, from) — move pointer. from: 0=start, 1=current, 2=end.
  • os Module for Files: os.path.exists(), os.rename(), os.remove(), os.getcwd(), os.listdir().
7
OOP — Part 1 & Part 2
Must Do ▶
  • Class & Object: class ClassName: ... obj = ClassName(). Class = blueprint. Object = instance. self refers to current object.
  • __init__ method: Constructor — called automatically when object is created. def __init__(self, params): ... Used to initialize instance variables.
  • Instance vs Class Variables: Instance variable: defined in __init__ with self. Class variable: defined outside any method, shared by all objects.
  • Inheritance: class Child(Parent): Inherits attributes and methods. Types: Single (1 parent), Multiple (multiple parents), Multilevel (chain), Hierarchical (1 parent many children). super() to call parent method.
  • Method Overriding: Child class redefines parent's method. Polymorphism via overriding.
  • Encapsulation: Private variables: __name (name mangling → _ClassName__name). Protected: _name (convention, not enforced). Getter/setter methods.
  • Polymorphism: Same interface, different behaviour. Duck typing in Python. Operator overloading with magic methods: __add__, __str__, __len__, __eq__.
  • Abstract Classes: from abc import ABC, abstractmethod. Abstract method must be implemented in subclass.
  • Magic/Dunder Methods: __str__ (str(obj)), __repr__, __len__ (len(obj)), __add__ (obj1+obj2), __init__, __del__. Write programs using these.
8
Exception Handling & Modules ⚠️ (Not in video — read separately)
Must Do ▶
  • Exception Handling: try: ... except ExceptionType: ... else: ... finally: ... try = code that may fail. except = handle specific error. else = runs if no exception. finally = always runs (cleanup).
  • Common Exceptions: ValueError (wrong type), TypeError (operation on wrong type), IndexError (index out of range), KeyError (dict key missing), FileNotFoundError, ZeroDivisionError, NameError, AttributeError.
  • raise Statement: raise ValueError("message") — manually raise exception. raise without argument re-raises current exception.
  • Custom Exceptions: class MyError(Exception): pass. Raise and catch your own exceptions.
  • Modules: import math — math.sqrt(), math.pi, math.ceil(), math.floor(). import random — random.random(), random.randint(a,b), random.choice(list), random.shuffle(list). import os — file/directory operations. import sys — sys.argv, sys.exit().
  • Creating Modules: Save functions in mymodule.py, then import mymodule or from mymodule import func_name. __name__ == '__main__' check.

1
Internet & Web Basics
Important ▶
  • Internet vs WWW: Internet = global network of networks. WWW = collection of web pages on Internet. Tim Berners-Lee invented WWW.
  • HTTP vs HTTPS: HTTP = HyperText Transfer Protocol. HTTPS = HTTP + SSL/TLS (secure). How HTTP works: Request → Server → Response. Status codes: 200 OK, 404 Not Found, 500 Server Error.
  • URL Structure: protocol://domain:port/path?query#fragment. E.g., https://www.example.com:443/page?id=1#section.
  • Web Browser vs Web Server: Browser = client that requests pages (Chrome, Firefox). Server = responds with pages (Apache, Nginx, IIS).
  • DNS: Domain Name System. Translates domain names to IP addresses. DNS hierarchy.
  • Client-side vs Server-side: Client-side = HTML/CSS/JS (runs in browser). Server-side = PHP/Python/Java (runs on server). Static vs Dynamic websites.
2
HTML — Complete Coverage
Must Do ▶
  • Document Structure: <!DOCTYPE html>, <html>, <head> (metadata), <body> (visible content). Every page must have this structure — exam practical must start with this.
  • Head Elements: <title> (tab name), <meta charset="UTF-8">, <meta name="viewport">, <link> (external CSS), <style> (internal CSS), <script> (JS).
  • Text Tags: <h1> to <h6> (headings), <p> (paragraph), <br> (line break), <hr> (horizontal rule), <strong>/<b> (bold), <em>/<i> (italic), <u> (underline), <s> (strikethrough), <sup> (superscript), <sub> (subscript), <pre> (preformatted), <blockquote>, <code>.
  • Lists: <ul> (unordered — bullets), <ol> (ordered — numbers), <li> (list item). <dl> (definition list), <dt> (term), <dd> (description). Nested lists.
  • Links: <a href="url">. target="_blank" (new tab), target="_self" (same tab). Absolute vs relative URLs. Anchor links: href="#id". mailto: and tel: links.
  • Images: <img src="path" alt="description" width="x" height="y">. alt attribute (accessibility + SEO). Image as link: wrap <img> in <a>.
  • Tables: <table>, <tr> (row), <th> (header cell), <td> (data cell). <thead>, <tbody>, <tfoot>. colspan (merge columns), rowspan (merge rows). border attribute. Nested tables.
  • Forms: <form action="url" method="get/post">. Input types: text, password, email, number, date, radio, checkbox, file, hidden, submit, reset, button. <textarea>, <select>+<option>, <label for="id">, <fieldset>+<legend>. Attributes: placeholder, required, disabled, readonly, maxlength, name, id, value.
  • Semantic HTML5 Tags: <header>, <nav>, <main>, <section>, <article>, <aside>, <footer>, <figure>+<figcaption>. Why semantic tags over <div> — SEO and accessibility.
  • Multimedia: <audio src controls>, <video src controls width height>, <source> inside them. <iframe src width height> for embedding.
3
CSS — Complete Coverage
Must Do ▶
  • CSS Syntax: selector { property: value; }. 3 ways to add CSS: Inline (style=""), Internal (<style> in head), External (<link> to .css file). Priority: Inline > Internal > External.
  • Selectors: Element (p), Class (.myclass), ID (#myid), Universal (*), Attribute ([type="text"]). Pseudo-class (:hover, :focus, :nth-child(n), :first-child, :last-child). Pseudo-element (::before, ::after, ::first-letter). Combinators: Descendant (div p), Child (div > p), Adjacent (h1 + p), Sibling (h1 ~ p).
  • Box Model: content → padding → border → margin. box-sizing: content-box (default) vs border-box. Margin collapsing. Padding vs Margin difference.
  • Display: block (full width, new line), inline (content width, same line), inline-block (inline but accepts width/height), none (hidden), flex, grid.
  • Positioning: static (default, in flow), relative (offset from normal position), absolute (removed from flow, relative to nearest positioned ancestor), fixed (relative to viewport), sticky (hybrid). z-index for stacking order.
  • Colors: Named (red, blue), Hex (#FF5733), RGB (rgb(255,87,51)), RGBA (rgba(255,87,51,0.5)), HSL (hsl(10,100%,60%)).
  • Typography: font-family (font stack with fallbacks), font-size (px, em, rem, %), font-weight (100–900, normal, bold), font-style (italic, normal), text-align (left, right, center, justify), text-decoration (underline, none, line-through), line-height, letter-spacing, text-transform (uppercase, lowercase, capitalize).
  • Background: background-color, background-image (url()), background-repeat (repeat, no-repeat, repeat-x, repeat-y), background-position, background-size (cover, contain, px), background-attachment (scroll, fixed). Shorthand: background: color url() repeat position.
  • Flexbox: Container: display:flex, flex-direction (row/column), justify-content (flex-start, flex-end, center, space-between, space-around), align-items (flex-start, flex-end, center, stretch), flex-wrap. Item: flex-grow, flex-shrink, flex-basis, align-self, order.
  • CSS Grid Basics: display:grid, grid-template-columns (e.g., repeat(3, 1fr)), grid-template-rows, gap. Grid is 2D, Flex is 1D.
  • Media Queries: @media (max-width: 768px) { ... }. Mobile-first approach. Breakpoints. Viewport meta tag is required.
  • CSS Transitions: transition: property duration timing-function delay. E.g., transition: background-color 0.3s ease. :hover effects.

JavaScript — Basics & DOM
Must Do ▶
  • Adding JS: Inline (onclick=""), Internal (<script> in body/head), External (<script src="file.js">). console.log() for debugging. alert(), confirm(), prompt().
  • Variables: var (function-scoped, can redeclare), let (block-scoped, can reassign, can't redeclare), const (block-scoped, can't reassign). Key differences — exam question.
  • Data Types: number, string, boolean, null, undefined, object, array, symbol. typeof operator. Loose (==) vs Strict (===) equality.
  • Operators: Arithmetic, Comparison (== vs ===), Logical (&&, ||, !), Ternary (condition ? a : b), typeof, instanceof.
  • Control Flow: if-else, switch-case (with break and default). for loop, while, do-while. for...of (arrays), for...in (objects).
  • Functions: Function declaration, Function expression, Arrow function (const f = (x) => x*2). Differences between them. Default parameters. Rest parameters (...args).
  • Arrays: Methods: push(), pop(), shift(), unshift(), splice(start,deleteCount,items), slice(start,end), concat(), indexOf(), includes(). Higher-order: map(callback), filter(callback), forEach(callback), find(callback), reduce(callback, initial).
  • DOM Manipulation: document.getElementById('id'), querySelector('selector'), querySelectorAll(). innerHTML, textContent, innerText. style.property. classList.add(), classList.remove(), classList.toggle(). setAttribute(), getAttribute(). createElement(), appendChild(), removeChild().
  • Events: addEventListener('event', callback). Common events: click, mouseover, mouseout, keydown, keyup, submit, change, load. event.preventDefault(). this inside event handlers.
  • Form Validation: document.querySelector('form').addEventListener('submit', function(e) { e.preventDefault(); validate(); }). Checking empty fields, email format, password length.
  • ES6 Features: Template literals (`Hello ${name}`), Destructuring (const {a,b} = obj), Spread operator (...arr), Object shorthand, let/const, Arrow functions.
  • Objects: Creating objects (literal, constructor). Accessing properties (dot notation, bracket notation). Methods in objects. Object.keys(), Object.values(), Object.entries().
